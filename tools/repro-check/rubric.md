# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | The repro report's environment record (usually its first block) read against the version, OS, and platform the issue targets. | Pass if the report names the project version or commit, the OS, and any runtime or driver the issue says matters, AND either that version matches what the issue targets or the report explicitly says it differs and why. Fail if there is no environment record, or if the report tests a different version or platform than the issue without saying so. | required |
| steps-rerunnable | The repro report's steps, from starting state (install or clone) to the trigger, including where every input comes from. | Pass if a stranger with only public access could re-run the steps without guessing: exact commands, inputs shown inline or from a public source. Terse is fine. Fail if any step depends on a private repo, an unshared file or config, or says "set it up" / "run it" without the actual command. | required |
| trigger-faithful | The report's input and command read against the trigger the issue states (its input, flags, syntax, and any maintainer note on what triggers it). | Pass if the element that triggers the bug (the specific input, syntax, operator, flag, or condition the issue or a maintainer says causes it) is kept, or any change to it is stated and explained. Harmless mechanics do not matter: http vs https, an offline/dry-run flag, a verbose flag, a local file instead of a URL, a different install path. Fail only if the triggering element itself was silently changed or skipped (a different operator, range syntax, unbound variable, missing required flag). | required |
| behavior-shown | The report's pasted artifacts (output, trace, exit code, log, measurement) read against the behavior the issue describes. For a CI/tooling gap issue, the behavior is the gap itself. | Pass if a verbatim artifact shows the issue's own symptom (same error type/message, exit behavior, or observable effect), OR it is an honest cannot-reproduce whose artifacts show the real attempt's outcome. Fail if there is no artifact, or the artifact shows a different or adjacent failure, or only shows that the program runs. | required |
| outcome-honest | The report's main conclusion (reproduced / not reproduced / cause) and any certainty words read against the artifacts actually shown. | Pass if the main conclusion matches what the artifacts show, and any root cause is labeled as a hypothesis. A cannot-reproduce that names what was tried and what differed passes. Brief side notes (a one-line control-run observation, "unchanged on the version I tested") do not fail this check. Fail only if the headline claim outruns the evidence: it says the reported bug reproduced when the artifact shows something else or nothing, asserts a root cause or certainty ("verified", "guaranteed", "confirmed on two machines") with no artifact behind it, or generalizes to versions or platforms it did not test. | required |
| claim-specific | The claim comment read against the issue. | Pass if the claim names something specific to this issue (the symptom, file, or trigger) and says the next step, promising only investigation or a report. Fail if it is a +1 / me-too, interchangeable assign-me boilerplate, or promises a fix, a PR, or a date/timeline. | required |
| repo-conventions | The repo-facts block's contribution policy (including any AI-use policy) read against both the claim comment and the repro report. Treat every package as AI-assisted work. | If the policy requires disclosing AI use in issues/comments, pass only if a comment actually discloses it (tool and extent); silence is a fail. If the policy only requires disclosure in PRs, only asks that comments be in the contributor's own words, or states no AI policy, pass unless the comments themselves visibly break a stated rule. | required |

## Verdict rule

accept only if every required check is pass. Any fail or unclear on a
required check means reject. unclear counts as fail. In a claim-only
live draft, the checks that need the repro report are reported
"not yet applicable" and left out of the verdict.

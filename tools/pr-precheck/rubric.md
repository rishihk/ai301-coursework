# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | The diff's changed files and hunks, read against the plan's stated files, its in-scope and not-in-scope lines, and its deviation notes; plus anything the description says about deferred or added work. | Pass if every hunk serves something the plan or its deviation notes name (tests that exercise the planned change count), and every deliverable the plan promises (code, tests, docs, configuration) appears in the diff. A planned item left out, or a change the plan did not name, still passes when the plan's deviation notes or the description disclose it plainly. Fail if the diff holds a hunk the plan does not name or puts out of scope (a new flag or option, a renaming pass, an unrelated file, reworded unrelated text), or a promised deliverable is missing, and nothing discloses it. | required |
| description-matches-diff | Every factual claim the description makes about what the change does, contains, or leaves out (such as exactly as planned, no changes outside X, the docs now document Y, adds a test), checked one by one against the diff and commit list. | Pass if every such claim is supported by the diff or the commit list. Judge claims by substance: loose counting or wording (for example one function touched when one function was edited and a small helper added for it) does not fail a claim that is true in spirit. Command output pasted into the description is evidence for repro-before-after, not a claim about the diff. Fail if the description claims fidelity, scope, a test, a documentation update, or behavior that the diff contradicts or does not contain, even when the change itself is good: for example exactly as planned or no changes outside X over a diff with an unplanned hunk, or docs updated with no documentation change in the diff. | required |
| repro-before-after | The test evidence, read against the plan's test plan and the repro evidence in the plan context: which command ran, on which code (before and after the change), and what output it printed. | Pass if the plan's primary repro (the issue's own failing case, as the plan's test plan re-runs it) is shown with real output both before the change and after it, the two outputs differ the way the plan said they should, and the run exercises the path the diff changes. Before and after may sit in one block or be labeled in the description or the evidence, as long as both outputs are shown. Any other step of the plan's test plan (a control, a side behavior, the project's own test suite) passes if its output is shown, or if the evidence states its result and a test added by the diff or a named repository check covers it. Fail if the primary repro is only a claim (tested locally, works now, tests pass), shows only one side, runs a control or an unchanged path instead of the primary repro, or shows no observable output. Also fail if a secondary step is neither shown, nor stated, nor covered by a test or check. Parts the plan or description honestly defers need no evidence. | required |
| repo-checks-run | The test evidence, read against the repository's own test, lint, and type-check commands named in the repo-facts block, the plan's test plan, or the template's testing checklist. | Pass if the evidence names the repository's own check commands that apply to the change and shows their result (output, counts, or an honestly reported failure with its reason). Fail if no repository check is shown, if the only claim is "tests pass" with no command named, or if checks the template or plan call for are absent. | required |
| diff-clean | Every added or removed line in the diff, plus the commit list. | Pass if every changed line serves the planned change: no leftover debug prints or logging, no commented-out code, no dead or unused functions or imports, no leftover TODO or work-in-progress markers, no formatting or whitespace-only churn, and no re-ordering of unrelated lines. Fail if any of these appears, even beside a correct fix. Commit titles such as "wip" or "misc cleanups" are supporting evidence, not the test. | required |
| template-asks-met | The repo-facts block's pull request template asks and contribution rules, read against the description and the diff. | Pass if every ask the repo-facts block states for a pull request is met: each template section has real content (or an explained not-applicable), the issue is referenced the way the template asks, and any artifact the repository requires in the change (a changelog or release-notes entry, tests, translations) is present in the diff. Fail if a stated ask is skipped, left blank, or left as template placeholder text. If the repo-facts block states no such asks, pass. | required |
| ai-disclosure | The repo-facts block's contribution policy on artificial intelligence, read against the description. | Pass if the description says, in the author's own words, how artificial intelligence was used whenever the repo-facts block states a policy that requires disclosure. If the block states no such policy, pass. Fail if a required disclosure is absent. | required |

## Verdict rule

Accept (ready to submit) only if all seven required checks pass. A preferred check never changes the verdict. A grade of unclear counts as fail. If the evidence a required check needs is missing from the package, that check is a fail, not unclear. An honestly disclosed shortfall is not a failure: work the plan or description plainly says was deferred or changed does not fail diff-matches-plan, description-matches-diff, or repro-before-after on its own. When the verdict is reject, quote the text of the first required check that failed.
